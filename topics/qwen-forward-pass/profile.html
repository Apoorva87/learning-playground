What took the time?

How to read timing, traffic and parallelism

The first strip locates each block by its observed start and end. Playback advances one block per step so you can read it. Bar widths retain the measured time scale. Token embedding and setup occur before block 0. Final normalization and vocabulary projection come after block 63. Stage timings nest inside their block.

Process CPU time adds time across the process’s threads. Dividing by wall time gives an average number of cores active during that interval. Independent math can still run sequentially. This capture measures CPU participation over an interval and cannot resolve simultaneous arithmetic instructions.

The weight chart counts a matrix’s stored bytes once per linear call and divides by its measured duration. Cache reuse, extra reads, activations and memory-controller behavior affect physical bandwidth. No device DRAM counter was available in this capture. The FLOP figure counts two operations per multiply-accumulate in linear projections, including the vocabulary head. Elementwise, attention and recurrence arithmetic are additional.

Where these numbers came from

During the real BF16 forward pass we captured the normalized, rotated query, cached keys, and cached values just before attention. We then expanded those exact values to FP32 and recomputed the scores, stable softmax and value mixture. The selected feature is before the learned output gate and output projection. All 17 positions are visible to this single query. Across 24 query heads the score and value matrix multiplications use 417,792 FLOPs when a multiply and add count as two. The FP32 replay has 24 KiB of queries, 68 KiB of unique keys and 68 KiB of unique values. Six heads can reuse each KV group. Whether a kernel materializes repeated copies changes its data movement.

Reproduce the investigation

The shared checkpoint contains 27,781,427,952 BF16 parameters, including the vision branch. These text-only passes exercise the language backbone and vocabulary head. We used the reference PyTorch recurrent kernels and eager full attention. Times are local observations from a warmed, instrumented run. Different kernels, machines and context lengths change the result.
