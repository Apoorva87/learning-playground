One Decoding Step by Hand

Imagine a decoder following a clue in an earlier sentence:

"The spare key is in the blue drawer. Open the …"

Use a smaller example with four cached token positions. During prefill, each attention layer saves a key (K) and a value (V) for each position.

Position Key kik_i Value viv_i
1 learned vector learned vector
2 learned vector learned vector
3 learned vector learned vector
4 learned vector learned vector

During decode, position 5 produces its query, key and value. The layer appends the new key and value to its cache. The query q5q_5 scores each eligible key, including k5k_5:

si=q5⋅kids_i = \frac{q_5 \cdot k_i}{\sqrt{d}}

Then softmax to get attention weights:

ai=exp⁡(si)∑jexp⁡(sj)a_i = \frac{\exp(s_i)}{\sum_j \exp(s_j)}

Finally, blend the values:

output5=∑i=15aivi\text{output}_5 = \sum_{i=1}^5 a_i v_i

Why is this safe? Causal attention means position 5 can only attend to positions 1–5 (including itself). With the same prefix, weights, position scheme and inference settings, positions 1–4 retain their earlier hidden states. Their keys and values are projections of fixed hidden states, so reusing them gives identical results as if you recomputed everything. The new query still reads history in dense attention, but the computation of earlier K/V pairs is saved.

The same cache, different queries produce different outputs. The keys and values stay fixed. Each query assigns its own weights.

Counting the cache bytes

For dense attention with equal key and value dimensions:

Bytes per token for one sequence = layers × KV heads × head dimension × 2 arrays × bytes per element. Multiply by tokens and batch size for the whole batch.

Our toy model

  • Batch = 1 (one sequence)
  • Layers = 32
  • Query heads = 32 (fixed)
  • Head dimension = 128 numbers
  • Bytes per number = 2 (BF16 or FP16)

One new token adds: 32×32×128×2×2=524,288 bytes32 \times 32 \times 128 \times 2 \times 2 = \mathbf{524,288\ bytes} = 512 KiB

The number of query heads can stay the same because several queries can use the same bank of keys and values. Each query still computes its own scores. These are architectures learned during training or adaptation. Changing the head count of a trained MHA model is a model change.

The Route from Separate Heads to Shared History

2017–2023: Share Across Heads

The original Transformer assigns different projections to each attention head. MQA gives all query heads one set of keys and values. GQA splits the query heads into groups, providing one KV set per group. This reduces stored bytes and the amount of KV data that must move during decode. Query heads can still attend to different positions.

2024: Store a Learned Latent

DeepSeek‑V2's multi-head latent attention (MLA) compresses the hidden state hh into a compact vector c=W↓hc = W_\downarrow h. Heads learn different projections of cc. In the content part of an attention score, q⊤(W↑c)=(W↑⊤q)⊤cq^\top(W_\uparrow c) = (W_\uparrow^\top q)^\top c. That identity lets an implementation score cached latents directly. A small positional key is cached separately for rotary position information. A latent costs fewer numbers per position while still supporting different heads.

2026: Compress Along the Sequence

V4‑Flash keeps a detailed recent window and represents older context with learned summary entries. Compressed Sparse Attention (CSA) forms summaries at a finer stride and chooses relevant ones for a query. Heavily Compressed Attention (HCA) forms much coarser summaries and can attend to all of them. Two costs are at play.

  1. Packing more tokens into each entry reduces how much history is stored.
  2. Selecting fewer stored entries reduces the work of reading them for the next token.

2026: Share Across Layers and Shrink Each Entry

DeepSeek‑V4.1‑Flash uses CSA2.

  • A Full layer writes a global cache and selects positions.
  • A Reindex layer reads that cache and picks positions for its own query.
  • A Reuse layer reads the cache and a preceding layer's selection.

Each layer still computes its own attention query and local sliding-window state. The window spans up to 128 tokens. The encoder's global entries cover pairs of positions. The decoder's cover single positions, with many layers reading the same store.

Follow the Rounding: FP4 Main Cache

The main global cache uses 4-bit numbers with a one-byte scale per group of 16.

  • Sixteen such values cost 8+1=9 bytes8 + 1 = \mathbf{9\ bytes}
  • Storing 16 BF16 values takes 32 bytes

That small example explains one ingredient. The model's overall cache also includes the indexer and benefits from sharing entries across layers. Its local sliding-window cache uses FP8.

What Fits in 890 MB?

Here is one way to reconstruct the reported global total:

Component Calculation Bytes per entry
Main entry (512-channel) 512/2+512/16512/2 + 512/16 288 bytes
Index key (128-channel) 128/2+128/32128/2 + 128/32 68 bytes
Total per entry 288+68288 + 68 356 bytes

Three encoder cache writers each create one entry per two tokens. One decoder writer creates one per token. Over a long sequence, the average is:

(3×12+1)×356=890 bytes per token(3 \times \tfrac{1}{2} + 1) \times 356 = \mathbf{890\ bytes\ per\ token}

Across the network, other layers can use those entries again. DeepSeek reports 890 bytes of global KV cache per token, about one quarter of V4‑Flash's corresponding footprint. At exactly 1,000,000 tokens that is 890 MB, about 849 MiB. Weights, the bounded local window, temporary activations, and allocator overhead require additional memory.

Why the gap? The toy architecture has 32 layers. DeepSeek-V4.1-Flash has 20 encoder and 20 decoder layers. Three encoder layers and one decoder layer write global entries. Other CSA2 layers reuse entries from an earlier writer.

  • Sequence compression changes the number of global entries. Each encoder writer produces one entry per pair of positions. The decoder writer produces one per position.
  • Cross-layer reuse changes how many global stores are needed. The first two encoder layers use only local attention.
  • Precision changes each entry’s byte cost. Sixteen main-cache values plus their scale occupy nine bytes. Each 512-channel main entry costs 288 bytes, and its index key adds 68.

The 128-channel toy head and the 512-channel main entry belong to different architectures. DeepSeek technical report, §§2.3, 2.4.4 and 4.2.1
