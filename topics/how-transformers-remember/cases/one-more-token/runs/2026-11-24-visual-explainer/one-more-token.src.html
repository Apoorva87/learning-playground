What does the next token reuse?

A transformer keeps earlier keys and values. Each new query decides how much to read from each value.

During prefill, each layer saves a key and a value for each prefix position. Causal masking makes earlier positions independent of future tokens. During decoding, the layer appends one more pair. Dense attention still reads the growing history on every step.

Predict the output if the query becomes zero. Then check.

Both dot products are zero. Softmax gives ½ and ½, so the same cache now returns (2 + 10) / 2 = 6.

32 queries can share one set of keys and values

For one sequence, multiply tokens × 32 layers × KV heads × 128 numbers per head × 2 arrays × 2 bytes. Multi-head attention adds 524,288 bytes per token. Sharing a KV head lets several queries score the same keys with different weights.

Double the tokens and halve the KV heads. Predict the memory change.

The two factors cancel. For example, 4,096 tokens with 8 KV heads and 8,192 tokens with 4 KV heads both use 512 MiB. These are hypothetical model designs.

How does DeepSeek reach 890 bytes per token?

Three encoder layers each write one entry per two tokens. One decoder layer writes one per token. Across a long sequence, that averages 3 × ½ + 1 = 2.5 entries per token.

356 B/entry × 2.5 entries/token = 890 B/token

A million tokens therefore use about 890 MB of global cache. Budget separately for the local 128-token windows, model weights, temporary activations, and serving overhead.

Two designs each read 512 entries per query. Must they occupy the same memory?

No. A design storing one entry per four old tokens holds roughly a quarter as many as one storing an entry per token, given equal entry sizes. The read count alone cannot tell you the inventory.
