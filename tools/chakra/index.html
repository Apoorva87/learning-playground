MLCommons Chakra

Chakra represents a workload as a stream of typed nodes. A reader can recover operator identities, input and output metadata, and the edges a producer encoded for simulation.

What an execution trace contains

The MLCommons schema begins with global metadata. Each following node has an ID, a name and a type. The schema makes room for control and data predecessors, microsecond timing, I/O descriptions and typed attributes. A producer decides which fields to populate and what each edge means in its capture.

From a capture to a portable graph

PyTorch’s ExecutionTraceObserver records operator nesting, tensor IDs, shapes and strides. Kineto’s CPU events supply timestamped intervals. The upstream linker combines host and device traces, including device launches where the capture contains them. A CPU host trace can also go straight to the converter. The converter encodes order for a replay engine. The jsonizer decodes messages for inspection. The visualizer can emit DOT or GraphML for an external graph tool.

Choose an edge deliberately

In the Qwen replay, transpose returns a new tensor ID pointing to the same storage. The score matmul receives that new ID. Matching its input to the transpose’s output answers “who produced this view?” The CPU parent ID answers “which call contained it?”

An ordering edge can force a simulator to serialize calls whose mathematical inputs are independent. Inspect the producer’s conversion rules before interpreting the graph. Upstream conversion rules

Run the Qwen trial

Install Git and uv. From the repository root, this command checks out the tested MLCommons revision and builds the Python package and its schema bindings with the upstream lockfile.

./install.sh chakra
CHAKRA=.local/tools/chakra/source/.venv/bin
"$CHAKRA/chakra_converter" --help

The browser study and saved protobufs open directly from the published files. Decode the small graph locally with the same CLI used in the trial.

case_dir=topics/qwen-forward-pass/chakra
"$CHAKRA/chakra_jsonizer" \
  --input_filename "$case_dir/attention.et" \
  --output_filename /tmp/qwen-attention.stream

Each message in the jsonizer stream is a JSON object. The saved decoded projection wraps those objects in an array for use in ordinary JSON readers.

To rebuild the browser study, supply the pinned PyTorch environment and the compact prefill and decode pairs built by the shared trace-selection script. The case script captures the saved FP32 replay, checks its outputs, runs the official converter, writes and decodes a second graph with tensor edges, and summarizes both whole-model phases. What the Qwen case tests

The study compares native converter output with a teaching projection containing one region and seven direct CPU calls. The raw ET and Kineto pair preserve every nested operation from the replay. The browser dependency walk, matched timestamp view and block-level summaries are additions built for the trial.

Select Mix values, follow Expand values, and then open Observed host time. Look for whether the key and value expansions overlapped. The full-model view lets you compare the fourth block during prefill and cached decode.
