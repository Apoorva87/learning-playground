Our example starts with an attention calculation written as two matrix multiplies and a softmax. The compiler recognized the pattern. Compare the original expression with the final wrapper to see which tensors had to be allocated.

Capture a graph of your own

Use the repository installer with a C++ toolchain and OpenMP available. On the tested macOS host, Apple Clang and Homebrew libomp supplied them. The installer uses Python 3.13 and verifies an actual compiled kernel.

./install.sh torchinductor
study=topics/qwen-forward-pass/torchinductor
python=.local/tools/torchinductor/.venv/bin/python
"$python" "$study/capture.py" attention
  1. Wrap the target function with torch.compile. Our backend saves the captured FX graph, then delegates to Inductor. A real input triggers compilation.
  2. Enable TORCH_COMPILE_DEBUG=1 to keep the transformed graph, scheduler IR before and after fusion, and generated CPU wrapper. Our capture uses a fresh local cache for each shape.
  3. Follow the names used by Runner.call. An empty_strided_cpu call requests storage. A reinterpret_tensor can give existing storage a new view.
  4. Measure warmed calls separately from compilation. The example also instruments generated function calls in a separate run so their ordering and returned tensor sizes can be inspected.
