What does the next token cost?

DeepSeek‑V4.1‑Flash averages 890 bytes of growing cache per token. Does a single extra token add 890 bytes? Follow two consecutive steps in HuggingArch’s model of the cache.

Compare two real architectures

Llama 3.2 1B stores new keys and values at every layer. DeepSeek V4.1 Flash keeps a short local window at each layer and shares compressed entries across layers. Compare the modeled backbone cache for one request on one rank, using each model’s own storage formats.

Count the writers

Llama adds a fixed amount each step

Each of its 16 layers appends a key and a value for each of 8 KV heads. Each vector holds 64 BF16 values at two bytes apiece. Its 32 query heads share those KV heads in groups of four.

16 layers × 2 vectors × 8 KV heads × 64 values × 2 bytes = 32,768 bytes per token

DeepSeek adds whole entries

The main compressed entry occupies 288 bytes and its index key occupies 68 bytes, including their scales. One writer allocates a 356-byte entry per token. Three more writers allocate one each per pair of tokens. HuggingArch rounds the number of stored pairs up. After the first token of a new pair, four new slots count toward the footprint. After the second, only the every-token writer needs another slot.

356 × (1 + 3 ÷ 2) = 890 bytes per token on average

Predict the change from 4,096 to 4,097, then to 4,098.

6,374,800 − 6,373,376 = 1,424 bytes, or four entries. Next, 6,375,156 − 6,374,800 = 356 bytes, or one entry. Together they add 1,780 bytes over two tokens.

Where the extra 2.73 MB goes

DeepSeek’s 40 local windows hold up to 128 entries of 528 bytes each. They account for 2,703,360 bytes once full. Two kinds of fixed compressor state add another 12,288 bytes each. Together these bounded tensors occupy 2,727,936 bytes per request. Their sizes come from the engine’s per-node storage records.

Predict the total backbone cache for 1,000,000 tokens.

The growing entries take 890,000,000 bytes at this even length. Adding the bounded state gives 892,727,936 bytes, the exact value from the engine. Model weights, serving buffers and allocator overhead each have a separate budget.

MB means 1,000,000 bytes. MiB means 1,048,576 bytes. These are analytical storage counts. This run downloaded no weights and measured no GPU memory.
