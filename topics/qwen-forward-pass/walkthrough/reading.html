1 / 16 · Text input

Look up one vector per token

The tokenizer turns the prompt into 16 integer IDs. The embedding table supplies one learned row for each ID. During the cached decode the caller supplies just ID 561, the token “ The”, at position 16 counting from zero.

Why this operation?

An ID identifies a vocabulary entry. Its learned vector gives the network numerical features to transform. Position IDs are prepared separately. Full-attention blocks use them when rotating queries and keys.

Tensor dimensions

Read a tensor shape from left to right. [1, 16, 5120] means one sequence, 16 token positions and 5,120 features at each position. The table is [248320, 5120]. Prefill reads 16 rows into [1, 16, 5120]. The next call reads one row into [1, 1, 5120].

2 / 16 · Block 0 · recurrent

Normalize the block input

Block 0 receives one 5,120-number vector per current token. It saves that vector for a skip connection and normalizes a copy for the token mixer. RMSNorm divides by the root mean square of the features and applies a learned scale.

Why this operation?

The skip path carries the existing representation intact to the addition. Normalization controls the magnitude seen by the new calculation. Every block preserves the outer width, so its update can be added element by element.

Tensor dimensions

Input, normalized input and skip path all have shape [1, T, 5120]. Statistics are calculated separately for each token over its 5,120 features, with epsilon 0.000001.

3 / 16 · Block 0 · recurrent

Project the query, key, value and gates

Four learned projections read the same normalized token vector. One packs the query, key and value together. The other three produce the output gate z and two numbers per value head that control writing and forgetting.

Why this operation?

The query chooses what to read, the key chooses where to write, and the value supplies the content. A sigmoid turns b into the write fraction β. The negative log decay g comes from a and two learned head parameters, so exp(g) gives the fraction of old memory to retain.

Tensor dimensions

Each B × T × 5,120 input produces 10,240 packed features, 6,144 gate features, and two sets of 48 control values per token.

Adapted Python

qkv = self.in_proj_qkv(x)
z = self.in_proj_z(x).reshape(B, T, 48, 128)
b, a = self.in_proj_b(x), self.in_proj_a(x)
beta = b.sigmoid()
g = -self.A_log.float().exp() * F.softplus(a.float() + self.dt_bias)

4 / 16 · Block 0 · recurrent

Mix four neighboring positions

Each of the 10,240 channels applies its own four learned weights to the current position and the three before it, then applies SiLU. The filtered channels split back into query, key and value heads.

Why this operation?

At the start of a fresh prompt, missing earlier positions contribute zeros. For the 17th token (index 16), cached decode combines the new projected input with indices 13, 14 and 15, giving the same causal window as processing that position in a longer prompt.

Tensor dimensions

The filter preserves B × T × 10,240. Q and K each reshape to B × T × 16 × 128. V reshapes to B × T × 48 × 128.

5 / 16 · Block 0 · recurrent

Correct the memory, then read it

Each of the 16 query/key heads serves three consecutive value heads. The rule L2-normalizes Q and K, decays the old state, then writes a β-scaled correction where the key’s prediction differs from the incoming value. Prefill evaluates the rule in chunks, while cached decode applies one update to the saved state.

Why this operation?

Imagine one memory entry holding 8, with key 1 and retention 0.5. After decay the prediction is 4, so an incoming value of 10 with β = 0.5 adds half the gap, or 3. The entry now holds 7, and the query reads from this updated state.

Tensor dimensions

Each block retains B × 48 × 128 × 128 state values across calls. For every new position, each of the 48 heads reads a 128-feature vector.

Adapted Python

# One token, one value head, and its shared query and key
q, k = l2norm(q.float()) / (128 ** 0.5), l2norm(k.float())
faded = g.exp() * state
predicted = k @ faded
delta = beta * (v.float() - predicted)
state = faded + torch.outer(k, delta)
read = q @ state

6 / 16 · Block 0 · recurrent

Gate what reaches the residual stream

RMSNorm rescales each 128-feature head read and applies its learned feature weights. The mixer multiplies the result by SiLU(z), joins the 48 heads and projects the joined vector to the model width.

Why this operation?

The same token can update memory for a later position while passing little of the current read into the block. The output gate makes that choice feature by feature, after the recurrent update has already occurred.

Tensor dimensions

B × T × 48 × 128 becomes B × T × 6,144. The output projection maps 6,144 features to 5,120 so the decoder can add the mixer result to the residual stream.

Adapted Python

rows = read.reshape(-1, 128)
inv_rms = (rows.float().square().mean(-1, keepdim=True) + 1e-6).rsqrt()
normed = self.norm.weight * (rows.float() * inv_rms).to(rows.dtype)
gated = normed * F.silu(z.reshape(-1, 128).float())
merged = gated.to(rows.dtype).reshape(B, T, 6144)
output = self.out_proj(merged)

8 / 16 · Block 0 · recurrent

Build new features for each token

Two independent projections of the same normalized input each produce 17,408 features. SiLU smooths the gate, and multiplication lets it select which features from the up projection pass through. A third matrix returns the result to 5,120 features for the second residual addition.

Why this operation?

The mixer let one token use information from the past. This gated MLP transforms each position’s own features. All positions share its weights. The two projections can be computed independently, but their product needs both results.

Tensor dimensions

Two [1, T, 17408] branches multiply element by element. The down projection produces [1, T, 5120], matching the residual. Each block has its own three MLP matrices.

Adapted Python

gate = silu(mlp.gate_proj(mlp_input))

10 / 16 · Block 3 · full attention

Project queries, keys, values and a gate

The query projection emits 12,288 numbers per token. Reshape to 24 groups of 512 and split each group into a 256-feature query and a 256-feature output gate. Two smaller projections each emit 1,024 numbers, forming four key heads and four value heads.

Why this operation?

A query asks which earlier positions matter. A key describes what a position can match. Its value carries the information to retrieve. Six query heads share each KV head, letting them ask different questions while retaining one copy of that group’s history.

Tensor dimensions

After reshaping, Q is [1, 24, T, 256]. New K and V are each [1, 4, T, 256]. The ungated readout will have 24 × 256 = 6,144 features. Head widths here are explicit model settings.

Adapted Python

11 / 16 · Block 3 · full attention

Encode position and append to the KV cache

Normalize each query and key across its 256 features. Rotary position embeddings rotate 64 of those features in pairs, leaving 192 untouched. Append each new rotated key and its corresponding value to this block’s own cache.

Why this operation?

A shared rotation rule makes a query–key dot product sensitive to relative position. The old keys already contain their positions, so the next step can reuse them. Queries and output gates are needed only for the current calculation.

Tensor dimensions

For decode, each of K and V grows from [1, 4, 16, 256] to [1, 4, 17, 256]. For prefill the cache starts empty. The stored keys and values are BF16, two bytes per element.

12 / 16 · Block 3 · full attention

Score earlier positions and mix their values

For each query, take its dot product with every visible key in its group. Divide by √256 = 16 and apply the causal mask. Softmax turns each row into weights summing to one. Multiply those weights by the values and sum over positions.

Why this operation?

A full-attention head can assign an individual earlier token a large weight. During prefill, each query sees its own position and earlier ones. During decode, the single new query can use all 17 positions. The cache saves recomputing old keys and values, while the new query still has to score the visible keys.

Tensor dimensions

Score grid [1, 24, T, L]. Prefill gives 16 × 16 scores per head before masking. Decode gives 1 × 17 per head. The resulting value mixture is [1, 24, T, 256].

Adapted Python

group = query_head // 6
scores = (q[:, query_head] @ K[:, group].transpose(-1, -2)) / 16
p = softmax((scores + causal_mask).float(), dim=-1).to(q.dtype)
mixed = p @ V[:, group]

16 / 16 · Model output

Turn the last position into vocabulary scores

Blocks 4 through 63 repeat the same three-recurrent, one-full pattern with distinct weights. The final RMSNorm rescales the last block’s output. This run requests logits for only the final current position, then a separate vocabulary matrix scores all 248,320 possible next-token IDs.

Why this operation?

The backbone works at width 5,120 regardless of vocabulary size. The output head maps those features back to token choices. The experiment fixes the next input so every tool sees the same cache. An ordinary generator could instead pick or sample a token from the scores.

Tensor dimensions

[1, T, 5120] → [1, 1, 5120] → [1, 1, 248320]. The untied output matrix has shape [248320, 5120]. A logit is an unnormalized score.
