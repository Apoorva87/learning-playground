DaCe

Trace a computation by asking which array elements must move. DaCe lets you express those movements, choose a schedule, and compile the graph into a native program.

Explore one Qwen decode token through six states

Read a graph from the inside out

A stateful dataflow multigraph (SDFG) connects states with control flow. Inside a state, a tasklet computes, a map identifies iterations, and a memlet carries a subset of an array along an edge. The subset can expose reuse even when two references point to the same underlying memory. DaCe’s explicit dataflow documentation

Run the saved case

  1. Install uv, Python 3.11 and a C++ compiler with OpenMP. On the tested Apple Silicon Mac, Apple Clang and Homebrew libomp supply the compiler and runtime. The recipe installs CMake into the tool environment.
  2. From the repository root, install the tested release and run the benchmark. 
    ./install.sh dace
.local/tools/dace/.venv/bin/python topics/qwen-forward-pass/dace/replay.py
  3. Open the six-state inspector. Choose Value mix, select query head 6 and token 16, then inspect the contribution of the newest cached value. Head 6 is the first query head to read KV head 1.

What you can change

The Python source uses DaCe’s graph-construction API. Each state contains a mapped arithmetic tasklet. Normalization and value mixing use separate workspaces so you can inspect intermediate numerical results. The SDFG can also be examined using the upstream viewer. Trial source · Upstream project and viewer instructions

DaCe compiles the graph and times an instrumented execution. The browser controls, byte accounting and explanations are teaching material built around that output. This trial exercised the CPU backend and sequential map schedule. GPU compilation, graph transformations, hardware memory counters and the IDE workflow remain untested here.
